## Мастер-чек-лист данных компании

Единый набор данных, который закрывает ~95% полей всех площадок — заполнить `company-profile.yaml` (шаблон рядом):

1. Legal name + DBA (если есть)
2. Организационно-правовая форма (LLC/Corp/…) и штат инкорпорации
3. EIN
4. UEI (уже есть — из SAM)
5. CAGE code (уже есть — из SAM)
6. Юридический и почтовый адрес
7. Контактное лицо (имя, должность)
8. Корпоративный email для тендеров
9. Телефон
10. Сайт
11. Описание компании (2–3 предложения, EN)
12. NAICS: 212319, 212321, 423810, 337127 (+ уточнить по каталогу)
13. Товарные коды: NIGP 750 / 020 / 545 / 755 / 760 / 420 / 425; UNSPSC сегменты 11, 30, 22, 56; PSC 5610, 3805, 3810, 7105, 7110, 7125
14. Число сотрудников и годовая выручка (для SBA size standard и полей форм)
15. Сертификации (SBE/MBE/WOSB/HUBZone/SDVOSB — если есть)
16. W-9 (подписанный PDF) — понадобится для FL и ряда площадок
17. Для NJ (перед award, не для регистрации): NJ Business Registration Certificate

## Правила безопасности

- **Пароли, API-ключи, cookies, токены в репозитории НЕ хранятся** — только в `.env` / secret storage (файл `.env` добавлен в `.gitignore`).
- В папках площадок хранятся только: статус, логин-URL, выбранные коды, настройки alerts, заметки.
- CAPTCHA, MFA и anti-bot не обходим. Юридические подтверждения (terms acceptance, certifications, подписи) выполняет только пользователь — система готовит данные и доводит до этого шага.
- Если площадка требует ручного подтверждения (email-верификация, звонок) — фиксируем в status.md и сообщаем пользователю.

## Процесс по каждой площадке

1. Открыть checklist.md площадки → собрать недостающие данные.
2. Заполнить формы (технически разрешённые поля), НЕ подтверждая юридических заявлений.
3. Передать пользователю шаги, требующие его действий (подпись/accept/оплата).
4. После активации: настроить alerts по товарным кодам, зафиксировать в status.md.
5. Обновить `platforms/platforms.yaml` → `registration_status`.
